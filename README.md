# AI 客服配置方法仓库

把本仓库地址交给调用方 Codex，它会自行取得并校验最新版方法包。仓库保存通用规则和工具，不保存客户资料、Bot 工作包或 Token。当前方法包版本：`025a18e0d3ab9169`。

## 现在进行到哪里

现有测试 Bot 已完成配置补丁的上传、预检、diff、发布和稳定回读联调。山雨测试 Bot 的状态机单项变更已发布至 R3，四组件摘要与计划一致，连续两次导出稳定；管理员确认本阶段真实对话由测试人员在企业微信端人工验证，当前仍待执行。新电脑可以安装并检查方法包；新人完整练习须等内部联调及负责人验收条件具备后再开始。正式环境写入默认关闭。

## 整体工作链路

1. **管理员准备平台**：初始化目标 Bot，完成 Agent 绑定、权限和能力目录，提供当前接口契约。
2. **调用方 Codex 取得当前配置**：验证身份、读取能力目录和 Bot 列表；员工明确选 Bot；核对配置上下文和 readiness，导出并校验可信工作包，保留只读基线。
3. **同一客户任务联合配置**：同一个调用方 Codex 依据客户资料和业务确认形成 SOP、跨板块变更计划；在同一工作副本中协调 Agent、状态机和知识库，标签按实际处理动作配置，只改受影响的文件并完成本地检查。
4. **调用方 Codex 上传，平台预检**：将工作副本打成配置补丁 ZIP 上传到所选 Bot；检查预检、版本冲突和四组件差异。上传成功仅表示平台收到包。
5. **人工审核后发布与验收**：负责人核对业务影响和完整 diff；预检放行后调用方发起发布，查询 operation、Release 与生效配置，再按本阶段确认的企微人工对话和渠道回执验证。反馈进入同一客户任务，由调用方从最新基线判断三块影响、修改、发布并复测；需要时按契约回退并复查。
6. **能力不足时继续原任务**：调用方提交标准化能力申请；管理员升级平台并发布新版能力目录；调用方重新读取目录和工作包后继续。

内部闭环通过后，新人先按虚构案例完成同一测试流程，经负责人验收，再接真实客户。正式客户仍从该客户自己的资料、Bot 列表和当前工作包开始。

## 三种东西分别放在哪里

| 名称 | 用途 | 位置 |
| --- | --- | --- |
| 本公开仓库 | 给各调用方 Codex 分发通用方法 | GitHub |
| 新人启动包 | 安装项目规则、Skill、案例、接口文档与工具 | 本仓库 `releases/` 中的 ZIP；安装后在新人本机 |
| Bot 可信工作包 | 某个 Bot 当前的真实可编辑配置，是每次修改的基线 | 从接口导出，留在该任务的私有工作目录；不上传 GitHub |

## 新电脑上的 Codex 怎么开始

1. 读取[引导脚本](./bootstrap.py)，核对 SHA-256 为 `d7c27652899a6b25ce2f7801a5a97a9b995262c45adb12e1aa61003faf47667b`；在本机 Python 3.11 执行 `bootstrap.py --output-root <本机工作目录>`。脚本按[当前版本索引](./latest.json)下载[启动包](./releases/025a18e0d3ab9169b9f28b1b284baed27947e430b1d549c335dc08a46e9bdb4d/startup.zip)，校验大小、摘要、包内清单和路径后解压。没有脚本运行条件时，Codex 按同一校验契约处理；校验失败即停止。
2. 使用脚本返回的 `project_dir` 作为本地项目，保留隐藏的 `.agents/skills/`，不覆盖现有项目或客户文件。读取包外 `先看这里.md`，再按任务读取包内规则、Skill 和当前平台契约。若 Codex 无法完成项目界面关联，只请求新人做这一步。
3. 核对安装与文件可读性。内部闭环通过并明确安排新人启用后，再开始 `练习案例/`；测试 Token、独立 ready Bot 和真实会话入口只在进入完整练习时由管理员准备。员工明确选 Bot，负责人确认业务规则、发布前 diff 和最终练习结果。不要把本地演练当成线上通过。

新人无需逐页读手册、手工安装 Skill 或复制提示词；Codex 负责执行和报告实际完成层级。

## 安装后到哪里找

| 项目内路径 | 内容 |
| --- | --- |
| `AGENTS.md`、`配置交付SOP链路.md` | 项目边界与完整交付流程 |
| `.agents/skills/` | 客服交付、Agent 配置及配套 Skill |
| `平台接口/`、`工具/配置补丁联调/` | 当前接口契约、导出和分步写入工具 |
| `练习案例/` | 虚构任务、管理员准备条件、负责人验收表 |
| `工具/经验同步/` | 通用方法更新与脱敏经验回传 |
| `客户/`、`Agent项目/` | 新任务的空目录；客户成果只留在本人私有项目 |

仓库根目录的 `latest.json` 是最新版本指针，`bootstrap.py` 是安装入口，`releases/` 保留不可覆盖的历史方法包。更早的管理员接口协作背景见[历史对接任务](./archive/调用方Codex与接口平台对接任务.md)；当前操作以启动包内的第二阶段契约为准。
