# 调用方 Codex：从这里开始

这是客服机器人配置开发的公开方法仓库。当前方法包版本：`bb02d4fe7cc9a6c5`。[版本声明](./latest.json)指向[新人启动包](./releases/bb02d4fe7cc9a6c5bc6177cbd94a81ba3902f1ac1307ff0d7a7e5a9902347ea8/startup.zip)。仓库不包含客户资料、工作包或 Token。

## 整体工作链路

先由内部调用方 Codex 与管理员完成测试环境的配置变更闭环；内部验证通过后，再让新人用本仓库启动包练习。每个真实客户仍由自己的调用方 Codex 按同一链路配置。

| 阶段 | 谁负责 | 要完成什么 |
| --- | --- | --- |
| 平台准备 | 管理员 | 建立或初始化目标 Bot，完成 Agent 绑定、权限及能力目录，提供当前接口契约和可导出的可信工作包。 |
| 选择与导出 | 调用方 Codex、员工 | 验证身份并读取能力目录和 Bot 列表；员工明确选择 Bot；核对配置上下文、绑定和 readiness，导出并校验当前工作包，保存只读基线。 |
| 配置开发 | 调用方 Codex、业务负责人 | 从客户资料形成并确认 SOP；制定 `change-plan.yaml`；在独立工作副本修改受影响的 Agent、知识库、状态机和标签，完成本地检查与联合场景测试。 |
| 上传与预检 | 调用方 Codex、接口平台 | 调用方将工作副本打成配置补丁 ZIP，上传到所选 Bot；平台检查版本冲突、引用和配置有效性，返回预检与差异。上传成功只说明平台收到包。 |
| 发布与验收 | 调用方 Codex、接口平台、业务负责人 | 人工核对预检和完整差异，放行后调用方发起联合发布；查询 operation、Release 和生效配置，再用真实会话及渠道回执验证；必要时按契约回退并复查。 |
| 能力缺口 | 调用方 Codex、管理员 | 当前能力不足时提交标准化申请；管理员升级平台并发布新版能力目录；调用方重新获取目录和工作包后继续原任务。 |

当前内部联调已经验证工作包导出和测试样本上传；R6 的三个样本均在预检阶段返回 `CONFIGURATION_INVALID`，尚未发布。管理员正在排查上游校验原因。此时停在预检，不把上传视为配置生效，也不把新人完整练习当作内部联调的替代。正式环境写入默认关闭。

以下是新人使用入口；包内 `配置交付SOP链路.md`、两个核心 Skill、第二阶段接口文档及联调工具负责执行细节。GitHub 只发布通用方法，新客户的配置工作包留在其私有项目中。

## 新人 Codex 的任务

内部闭环通过并安排新人启用后，新人只需把本仓库地址交给你。请自行取得并校验最新版启动包，在新人电脑建立独立的本地项目，读取随包 Skill 和当前平台契约，开始“星禾口语课程咨询”的配置练习。按实际资料和任务阶段调用本机可用的其他 Skill。能在本地完成的工作立即完成；进入完整写入练习时，再核对该新人获分配的测试环境条件。不要要求新人阅读手册、手工安装 Skill 或复制提示词，也不要把本地演练说成线上闭环通过。

## Codex 执行入口

1. 读取[引导脚本](./bootstrap.py)，核对其 SHA-256 为 `d7c27652899a6b25ce2f7801a5a97a9b995262c45adb12e1aa61003faf47667b`，再用本机 Python 3.11 执行 `bootstrap.py --output-root <新人自己的工作目录>`。脚本从本仓库 `main/latest.json` 取得当前 ZIP，核对字节数、SHA-256、包内清单和路径后解压，并输出本地项目路径；任一校验失败即停止。没有脚本运行条件时，可按同一契约自行执行这些检查。
2. 使用引导脚本返回的 `project_dir` 作为 Codex 本地项目，不重复解压。已有同名项目或客户文件时不要覆盖；核对当前版本后选择新目录或按包内同步工具更新通用文件。保留隐藏的 `.agents/skills/`。
3. 读取包外 `先看这里.md`，再读项目内 `AGENTS.md`、`配置交付SOP链路.md`、随包 Skill、`平台接口/第二阶段-20261003/` 的三份当前契约、`练习案例/练习任务.md` 和联调工具 README。按文件类型与实际工作选用本机已可用的资料处理 Skill；新 Codex 自行执行可用性检查，不要求新人代读这些文件。
4. 直接从虚构案例开始：在 `练习/星禾口语课程咨询/` 保存 SOP、已确认与待确认事实、跨板块变更计划和测试记录。管理员提供测试环境 ready Bot 与员工 Token 后，按当前 Bot 列表由员工明确选目标，导出可信工作包，再在独立工作副本修改 Agent、知识库、状态机和按需启用的标签；完成静态检查。
5. 内部闭环通过、隔离练习 Bot、真实会话入口和发布条件具备后，按第二阶段契约分步上传、预检、审阅 diff、发布、回读、实测与回退。预检有 blocker 就停止并记录证据。负责人审核完整练习通过后才开始真实客户任务；正式环境写入默认关闭。

新人不必理解接口细节或手册，Codex 应按项目 Skill 与契约执行。外部条件未齐时，先完成不依赖它们的真实本地练习，并准确记录尚未验证的环节。

## 方法更新

`latest.json` 指向当前校验版本，`releases/` 保留历史版本。后续通用方法通过项目内 `工具/经验同步/` 更新；脱敏反馈只向另行配置的私有反馈仓库提交，未接通时留在本机。客户资料、配置、工作包和凭据始终留在各自私有目录。
