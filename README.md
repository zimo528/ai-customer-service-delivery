# AI 客服配置方法仓库

把本仓库地址交给调用方 Codex，它会自行取得并校验最新版方法包。仓库只分发通用 Skill、项目规则、管理员契约和工具，不存客户资料、Bot 工作包或 Token。当前方法包版本识别号：`1.1.12`。

## 从这里开始

1. Codex 读取[引导脚本](./bootstrap.py)，核对 SHA-256 为 `9e24caf9de2685b1bf81ccc6097f63f0499bac59a45d5f1b1171e44d30d0e8a4`，在本机 Python 3.11 执行 `bootstrap.py --output-root <本机工作目录> --expected-version 1.1.12`。脚本按[最新版本索引](./latest.json)下载[方法包](./releases/22872818d6e06673cd22162dac9ec8865233e0b1b30440b2f5a25da96c5bc451/startup.zip)，校验版本、大小、摘要、包内清单和路径后解压；校验失败即停止。刚发布后若公开索引暂时仍返回旧版，稍后重试，不用旧版继续开工。
2. 以返回的 `project_dir` 作为本地项目，保留隐藏的 `.agents/skills/`。先读包外 `先看这里.md`、项目 `AGENTS.md`、`本地项目目录约定.md`、两个核心 Skill 和平台接口索引。不能由 Codex 完成项目界面关联时，只请用户完成这一项。
3. 当前接收仓库地址的对话就是主控／总控（同一个对话），关联项目后由它创建每个客户的独立任务，不另建第二个控制对话。核对项目级 Skill、运行参考、Agent 案例、工具和本机环境；平台员工 Token 由总控在本机项目根目录 `.platform-staff-tokens.json` 保存一次，客户任务按环境复用。用户给出客户姓名与机器人类型后，在总控查重并创建真实客户任务。无虚构练习或练习签字门槛。

## 实际配置链路

管理员准备 Bot、绑定和能力目录。客户任务若处理已存在 Bot，先按管理员指南在所选环境验证身份、读取能力目录和 Bot 列表，由员工明确选择 Bot，读取配置上下文并确认 readiness，导出并校验可信工作包。按原路径解压并保留只读基线，阅读包内 `AGENTS.md`、`dclaw-manifest.json`、`platform/` 与实际配置，再结合客户资料形成可确认 SOP 和包内模板要求的 `change-plan.yaml`；在工作副本中生成受影响的 Agent、DClaw 知识内容、中台状态机及按需标签。尚无 ready Bot 或平台条件时，只先做资料清洗与非部署 SOP 草案，平台绑定开发标为待接入。三块使用同一客户规则，并用同一组场景核对答复、依据、阶段和处理动作。各判断框的证据、通过条件与失败去向见包内交付 Skill 的 `references/delivery-gates.md`。

制定方案时对照动态能力目录与运行机制；确认能力不足就提交有证据的能力申请，管理员升级后重新读取能力目录与工作包。本地检查或后续效果验证新发现的缺口同样按此分支处理。能力足以实现的部分按当前环境开放契约上传、预检、核对四组件 diff；负责人确认业务影响且预检有效后发布，通过 operation、Release 与配置回读确认本轮配置生效。结果不明先查原 operation 和幂等状态；`RECOVERY_REQUIRED` 停止并交管理员恢复。真实对话、渠道回执和必要回退按具体任务或异常另行执行。测试环境已开放第二阶段写入闭环；正式环境须核对管理员对本次目标的开放证据和当前契约，已开放时可直接从正式环境开始。缺少平台条件时继续可确认的本地配置，明确记录待接入状态。

本公开仓库保存方法包；Bot 可信工作包从接口按 Bot 与环境导出，留在相应私有客户任务，绝不上传本仓库。历史方法包保留在 `releases/`，`latest.json` 指向当前版本。更早的对接背景见[历史对接任务](./archive/调用方Codex与接口平台对接任务.md)。

Skill 放在项目级 `.agents/skills/`；已有同名用户 Skill 时核对实际选用版本。调用方无需 GitHub 账号，方法包可从本公开仓库取得。经验回传使用私有反馈仓库专用 Token，在本机交互式终端输入并保存在系统支持的 Git 凭据管理器；首次脱敏测试反馈取得私有 Issue 回执后，才在调用方总控启用每日检查。未接通时继续客户配置。平台写入由客户任务按契约分步执行。
